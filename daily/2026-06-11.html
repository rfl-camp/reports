GPU / DRM 驱动

nova-core：GSP 卸载状态迁移到固定的 Gpu 子对象

这组 4 个补丁由 Alexandre Courbot（NVIDIA）和 Eliot Courtney 等人协作完成。它把 GSP 固件卸载（unload）时需要保存的状态，从原来散落在各处的位置，集中搬到了一个"被钉住的（pinned）"Gpu 子对象里。为什么要"pin"呢？因为在 Rust 里，某些数据结构一旦被创建就不能在内存中移动位置（比如包含自引用的结构），pin 机制保证了这一点。这次重构让 GSP 卸载流程更清晰、更安全，也为后续功能扩展打下基础。Gary Guo 在审核中提出了多处改进建议。

nova-core：从 GSP 提取可用显存（FB）区域

这组同样是 4 个补丁，目标是让 nova-core 驱动能从 GSP 固件获取到"哪些显存区域是可以用的"这个关键信息。想象一下：显卡有好几 GB 的显存，但并不是所有区域都能随意使用——有些被固件占了，有些被硬件保留了。这组补丁让驱动能精确知道"安全可用"的显存范围，为后续的显存分配和管理做准备。Timur Tabi 和 Gary Guo 参与了审核讨论。

nova-core：用 c"literal" 替换 c_str!() 宏

Gary Guo 提交了 2 个补丁，把 nova-core 代码中所有的 c_str!("...") 宏调用换成了 Rust 原生的 C 字符串字面量语法 c"..."。这是 Rust 1.77 引入的新特性——以前要在 Rust 里写 C 风格的以 \0 结尾的字符串，需要用一个自定义宏，现在语言本身就支持了。虽然功能上没有变化，但代码更简洁、更符合惯用写法（idiomatic），也减少了对自定义宏的依赖。

drm: gpuvm 要求 Send 和 Sync

Alice Ryhl 提交了第 3 版补丁（2 个补丁），要求 GpuVm（GPU 虚拟内存管理器）的共享数据必须实现 Send 和 Sync trait。这是 Rust 的线程安全机制——Send 表示数据可以安全地在线程间传递，Sync 表示多个线程可以同时安全地读取它。GPU 虚拟内存管理天然涉及多线程访问（多个应用可能同时使用 GPU），所以这个约束是必要的。加上这个约束后，编译器会在编译时就帮你检查是否有线程安全问题，而不是留到运行时才崩溃。

内存管理

内存管理

SafePage：用类型系统防止内存页的数据竞争

Alice Ryhl（Google）提交了第 2 版补丁（2 个补丁），引入了一个全新的 SafePage 类型。在内核中，"页"（page）是内存管理的基本单位（通常 4KB）。问题是，普通的 Page 类型允许多个地方同时读写同一个页面，这可能导致数据竞争（data race）——一种难以调试的并发 bug。SafePage 通过 Rust 的类型系统来保证：如果你持有一个 SafePage，就意味着没有其他人能同时修改它。这就像你在图书馆借了一本书，在你还书之前别人看不到也改不了它。Miguel Ojeda 和 Andreas Hindborg 参与了审核。

📬 查看补丁

NumaNode::id() 访问器

Alice Ryhl 提交了一个小补丁，给 NumaNode 类型添加了一个 id() 方法。NUMA（Non-Uniform Memory Access，非统一内存访问）是多处理器系统中的一种内存架构——不同的 CPU 访问不同区域的内存速度不一样，就像你到离自己近的超市购物更快一样。每个"节点"代表一组 CPU 和与之最近的内存。这个方法让 Rust 代码能方便地获取某个 NUMA 节点的 ID，在分配内存时可以选择"离当前 CPU 最近的内存"，从而提升性能。

📬 查看补丁

Align 类型：编译期内存对齐

Gary Guo 提交了第 2 版的 Align 类型补丁。内存对齐是底层编程中非常重要的概念——CPU 通常要求数据存放在特定倍数的地址上（比如 4 字节对齐、8 字节对齐），不对齐的访问在某些架构上会导致性能下降甚至硬件异常。这个 Align 类型让你在编译期就能表达和检查对齐要求，相比运行时检查更安全、零开销。

块设备层

块设备操作的 QueueData 要求 Sync

Alice Ryhl 提交了一个补丁，要求块设备操作（Operations）中的 QueueData 关联类型必须实现 Sync trait。块设备就是硬盘、SSD 这类存储设备，QueueData 是与 I/O 请求队列关联的自定义数据。因为多个 CPU 核心可能同时处理 I/O 请求，它们会同时访问这个共享数据，所以必须保证它是线程安全的。Gary Guo 参与了审核。

hardening：为 Rust 默认关闭 randstruct

Kees Cook 提交了一个补丁，在启用 Rust 的情况下默认关闭 randstruct（结构体随机化）。randstruct 是 Linux 内核的一个安全加固特性，它会随机打乱结构体中字段的排列顺序，让攻击者更难利用内存漏洞。但问题是，Rust 代码通过 FFI 访问 C 结构体时需要知道字段的确切布局，randstruct 打乱后会导致不兼容。这个补丁让 allmodconfig（编译所有模块的配置，常用于 CI 测试）在 Rust 环境下能正常工作。Miguel Ojeda 参与了讨论。

Binder 驱动

rust_binder：为 Node::add_death 添加所有权断言

Georgios Androutsopoulos 提交了一个补丁，修复 Rust 版 Binder 驱动中的一个安全不变量（safety invariant）问题。Binder 是 Android 系统中进程间通信（IPC）的核心机制——当你在手机上从一个 App 切换到另一个 App 时，它们之间就是通过 Binder 传递消息的。

具体来说，代码中有一个 NodeDeath::set_cleared 方法，它的 // SAFETY: 注释假设了一个前提条件：一个 NodeDeath（节点死亡通知）永远只会被加入到它"所属"节点的死亡列表中。但问题是，Node::add_death 这个安全函数（safe function）在实际插入时并没有检查这个条件！这意味着理论上可以把一个 NodeDeath 错误地加入到别的 Node 的死亡列表中，违反了安全注释中声明的不变量。这个补丁添加了所有权断言来强制执行这个检查。Miguel Ojeda 和 Gary Guo 等 4 人参与了审核。

字段投影（Field Projections）与 RCU

Boqun Feng 在 Zulip 上发起了关于"字段投影"和 RCU 的讨论。字段投影是 Rust 社区正在设计的一个语言特性，允许你安全地从一个智能指针"投影"到内部字段——比如从 Pin<&mut Struct> 得到 Pin<&mut Struct.field>。RCU（Read-Copy-Update）是内核中一种高效的并发原语，让读操作几乎零开销。Boqun 表示喜欢用 Shield（护盾）这个名字来称呼 RCU 的读侧保护——确实比技术术语"read-side critical section"要直观得多！这种命名上的讨论看似小事，但好的 API 命名能大大降低学习门槛。

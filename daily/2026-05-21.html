DRM 子系统：用「高阶生命周期」管理驱动私有数据

DRM 子系统：用「高阶生命周期」管理驱动私有数据

Danilo Krummrich 和 Boris Brezillon 正在讨论一组 6 个补丁，核心问题是：GPU 驱动在运行时需要把自己的私有数据（比如 GPU 的状态信息）绑定到 DRM 框架提供的结构体上。在 C 语言里，这通常用 void* 指针随便指，但 Rust 要求严格的生命周期检查。这组补丁引入了「Higher-Ranked Lifetime」（高阶生命周期）的技巧，让编译器能在不牺牲安全性的前提下，灵活地表达"这个私有数据的生命周期取决于谁拥有它"这种关系。这对于正在开发中的 Nova（NVIDIA 开源 GPU 驱动）尤其重要，因为 Nova 大量依赖 DRM 框架的 Rust 绑定。

Asahi GPU 驱动：GEM SHMEM 内存管理即将提交新版本

PCI 驱动 Trait 增加生命周期参数（v3，27 个补丁）

PCI 驱动 Trait 增加生命周期参数（v3，27 个补丁）

Eliot Courtney 提交了第三版补丁，目标是让 PCI 驱动的 Driver trait 支持生命周期参数。简单来说，以前 Rust 写的 PCI 驱动没法精确地告诉编译器"我借用的这个数据会活多久"，这在复杂驱动中可能导致安全问题或需要大量 unsafe 代码。新方案通过给 Driver trait 加上泛型生命周期，让编译器可以自动检查数据的有效期，减少手动管理内存的负担。这组补丁高达 27 个，涉及对整个 PCI Rust 绑定的重构，NVIDIA 的工程师也参与了 review。

Auxiliary 总线驱动注册泛化为 ForLt（v3，27 个补丁）

Auxiliary 总线驱动注册泛化为 ForLt（v3，27 个补丁）

Danilo Krummrich 和 Gary Guo 合作的这组大型补丁系列，对「辅助总线」（Auxiliary Bus）的驱动注册流程进行了泛化改造。之前的注册 API 是写死的，现在改用 ForLt（一种高阶生命周期的抽象）来参数化，使得注册逻辑可以适应不同驱动的需求。这就像是从"只能点固定套餐"变成了"可以自由搭配菜品"——驱动开发者在注册设备时有了更大的灵活性。这个改动是 DRM 和 PCI 驱动框架演进的基础，多个下游驱动都依赖它。

Alistair Francis 提交了一组 18 个补丁，为 PCI 子系统添加对 TSM（TEE Security Manager）和 CMA（Component Measurement and Attestation，组件度量与认证）设备的支持。这是跟硬件安全相关的功能——简单说，就是让 Linux 内核能够验证插在 PCIe 总线上的设备是否可信、没有被篡改。在机密计算（Confidential Computing）场景下，比如云服务器上运行敏感任务时，这个功能非常关键。补丁目前收到了初步 review。

内存同步与 RCU

内存同步与 RCU

新增 call_rcu() 的 Rust 抽象

新增 call_rcu() 的 Rust 抽象

Philipp Stanner 提交了一个重要补丁，为内核的 RCU（Read-Copy-Update）机制添加了 call_rcu() 的 Rust 安全封装。RCU 是 Linux 内核中最核心的并发同步机制之一——想象一下，多个 CPU 核心同时在读取一份共享数据，而某个核心想要修改它。RCU 的做法是：先复制一份新的，修改新副本，然后等所有正在读旧数据的核心都读完了，再安全地释放旧数据。call_rcu() 就是"等大家都读完后，帮我执行这个回调函数来释放资源"的接口。

Boqun Feng 参与了 review。补丁的设计思路是让用户只需要传入数据，框架会自动在"宽限期"（grace period）结束后释放，不需要手动管理复杂的回调逻辑。这个抽象预计会被 GPU 驱动、文件系统、网络子系统等大量使用。

modpost 脚本：增大 buf_printf 缓冲区

modpost 脚本：增大 buf_printf 缓冲区

Gary Guo 和 Alexandre Courbot 提交了一组 7 个补丁，目标是增大内核构建工具 modpost 中 buf_printf 函数的缓冲区大小。modpost 是内核编译过程中的一个关键脚本，负责处理模块的符号表和依赖关系。随着 Rust 代码引入内核，符号名称变得更长（Rust 的命名空间和泛型会生成很长的符号名），原来的缓冲区不够用了，可能导致构建时信息被截断。这个补丁就像"把水管换粗一号"，确保更长的符号名也能正确处理。

configfs 属性声明：用过程宏替代旧宏

Malte Wechter 提交了一个补丁，用基于 syn 库的过程宏（procedural macro）重新实现了 configfs_attrs! 宏。configfs 是内核提供的一种配置文件系统，允许用户通过文件操作来配置内核子系统（比如 USB gadget 配置）。以前声明 configfs 属性的宏是用 macro_rules! 写的，语法复杂、报错信息差。新的过程宏使用 syn（Rust 社区标准的语法解析库）来解析输入，可读性和错误提示都大幅提升。补丁同时删除了旧宏，更新了所有调用处，并在 MAINTAINERS 文件中注册了新文件。kernel test robot 已经运行了自动化测试。

新手贡献机会（GOOD FIRST ISSUE）

新手贡献机会（Good First Issue）

① 把 addr_of! / addr_of_mut! 替换为新语法 &raw [mut] place

如果你正在找第一个内核贡献的机会，今天有两个标记为 good first issue 的任务值得关注：

① 把 addr_of! / addr_of_mut! 替换为新语法 &raw [mut] place

Rust 语言最近稳定了一种新的获取裸指针的语法：&raw const x 和 &raw mut x，用来替代之前的 addr_of!(x) 和 addr_of_mut!(x) 宏。新语法更简洁、更符合 Rust 的表达习惯。这个 Issue 需要你在内核的 Rust 代码中全局搜索旧宏调用，逐一替换为新语法。是一个非常好的"熟悉内核 Rust 代码结构"的练手任务。由 BennoLossin 创建。

🔗 查看 Issue #1148
② 将 PhysAddr 类型别名转为 newtype

② 将 PhysAddr 类型别名转为 newtype

目前内核 Rust 代码中的 PhysAddr（物理地址）只是 u64 的类型别名（type alias），这意味着编译器不会阻止你把一个普通数字当成物理地址使用，容易出 bug。这个 Issue 要求把它改成 newtype（即 struct PhysAddr(u64)），这样编译器就能帮你检查"这里需要的是物理地址，不是随便一个数字"。由维护者 ojeda 亲自创建，是学习 Rust 类型系统如何提升内核安全性的绝佳案例。

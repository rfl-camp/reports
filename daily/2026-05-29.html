SRCU 同步原语 — Rust 抽象第 7 版

补丁 1：添加 SRCU 辅助函数

今天最重磅的补丁系列来自 Onur Özkan，在 Alice Ryhl、Paul E. McKenney、Gary Guo 等多位核心开发者的审阅下，SRCU 的 Rust 封装已经迭代到了第 7 版。这个系列由 4 个补丁组成，目标是为 Rust 代码提供一套安全、符合 Rust 惯例的 SRCU 接口。

为什么需要这个？ SRCU 全称"Sleepable Read-Copy-Update"，是 Linux 内核中一种特殊的同步机制。普通的 RCU 在读取数据时不能睡眠（即不能执行可能阻塞的操作），但 SRCU 可以。这对 GPU 驱动特别重要——比如正在开发的 Tyr 驱动的 reset 基础设施需要用 SRCU 来保护"硬件正在重置"和"正常访问硬件"这两条路径不会互相打架。

在 rust/helpers/srcu.c 中添加了 C 语言的 FFI 辅助函数，让 Rust 代码能够调用底层的 SRCU API。这是"桥梁"层——因为 Rust 不能直接调用 C 的内联函数和宏，需要这些辅助函数作为跳板。

补丁 2：暴露 srcu_readers_active() 接口

这个补丁把 srcu_readers_active() 函数从 kernel/rcu/srcutree.c 的实现文件移动到了 include/linux/srcutree.h 头文件中，使其变成一个内联函数。这样做是为了让 Rust 端的辅助函数 rust_helper_srcu_readers_active() 能够正确调用它。同时还为 Tiny SRCU（精简版 SRCU）也添加了对应的实现，确保不同的内核配置都能正常工作。

⚙️ 中断与锁机制

⚙️ 中断与锁机制

计数式中断禁用/启用（v2，12 补丁系列）

Boqun Feng 和 Peter Zijlstra 在推进一个大型补丁系列（12 个补丁），引入计数式中断禁用/启用机制。目前内核的中断禁用是"二元"的——要么开，要么关。但如果嵌套调用（比如函数 A 禁用了中断，函数 A 调用函数 B，函数 B 也禁用了中断），退出 B 时会错误地重新启用中断。计数式机制通过维护一个计数器来解决这个问题：每次禁用 +1，每次启用 -1，只有计数归零时才真正启用中断。Peter Zijlstra（内核锁机制的核心维护者）已经给出了审阅意见。

📬 查看补丁
锁清理守卫切换到新的 IRQ 变体（v2，12 补丁系列）

同一系列的配套补丁——在锁的"清理守卫"（cleanup guards）中，将旧的中断禁用/启用调用切换为新的 _irq_{disable,enable}() 变体。清理守卫是一种确保"不管代码执行路径如何，锁一定会被释放"的机制（类似 Rust 的 Drop trait）。这个改动让这些守卫使用上面新引入的计数式接口，保证嵌套使用时的正确性。

📬 查看补丁

Heiko Carstens 提交的补丁为 s390 架构启用 HAS_SEPARATE_PREEMPT_RESCHED_BITS 特性，Boqun Feng 和 Peter Zijlstra 参与审阅。这与上面的中断计数系列密切相关——将抢占计数和重新调度标志分离到不同的位中，让调度器可以更高效地判断"现在是否需要切换进程"。

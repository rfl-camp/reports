内存与类型系统：Ownable/Owned 所有权工具（v19 大系列）

这是今天体量最大、最值得关注的一组工作，由三星的 Andreas Hindborg 牵头，集合了 Asahi Lina、Oliver Mangold 等人的贡献，一共 8 个补丁，已经迭代到第 19 版了。核心目标只有一句话：让 Rust 安全地「拥有」那些原本属于 C 语言的内核对象。

为什么需要它？内核里很多数据结构（比如内存页 struct page）是 C 写的，Rust 代码要用它们，就得搞清楚「这块东西到底归谁管、谁负责释放」。在这之前 Rust-for-Linux 已经有了 AlwaysRefCounted（永远靠引用计数管理）这套机制，但有些对象的情况更微妙：有时候它是「唯一归我所有」的，有时候又是「大家共享」的。这一系列就是来补齐这种中间地带的。

① 新增 Ownable trait 与 Owned 类型（系列总览 + 核心补丁）：作者类比已有的 AlwaysRefCounted/ARef，提出一个新概念——Ownable 类型是那种「可以被 Rust 拥有、但不强制」的 C 对象。和引用计数不同的是，这种所有权要求引用在 Rust 这边是「独一份」的，不允许随便复制。这样就能明确表达「这个 C 对象现在完全交给 Rust 管，用完由 Rust 负责销毁」。补丁还顺手让 Owned 实现了 ForeignOwnable，方便把它塞进 XArray 这类容器里。

📬 查看补丁（系列总览）

② 把 AlwaysRefCounted 改名为 RefCounted：这一步其实是个重要的概念拆分。Oliver Mangold 指出，有些类型既可能用引用计数管理、又可能被独占拥有。如果还允许从一个 &Owned（独占借用）里直接造出 ARef（计数引用），那就「不健全」（unsound，意思是可能引发内存安全漏洞）。所以他们把原来的 AlwaysRefCounted 一分为二，名字也更简洁了。

③ 新增 OwnableRefCounted：这是上面拆分后的「桥梁」。实现了这个 trait 的类型，可以安全地在 ARef（共享计数引用）和 Owned（独占所有权）之间来回转换。典型场景是：某个对象平时大家共享着用，但它有些方法只有在「我是唯一持有者」时才能安全调用——这个 trait 就让这种转换变得有规可循。

📬 查看补丁

④ 内存页 Page 改用新机制：作为这套抽象的第一个「真实用户」，内存页类型被改造成了 Ownable。这样 Page 的引用可以以「借用」的形式返回，而不必非得拥有底层的 struct page。配套地，旧的 BorrowedPage 类型被删掉，所有用到它的地方都改用 Owned；还新增了一个 from_raw() 方法，能从原始的 struct page 指针构造出一个 Page 实例。

I/O 抽象与投影：更安全地读写硬件寄存器（v5，20 补丁）

这组工作出自 Gary Guo，主题是「I/O 类型的泛化与投影（projection）」，体量也很大——20 个补丁。要理解它，先要知道驱动程序干活的基本方式：硬件设备会把自己的控制开关「映射」成一段内存地址，驱动通过往这些地址读写数据来指挥硬件。这套补丁就是在改进 Rust 这边描述这种「I/O 内存区域」的类型，让它们更通用、更安全。

① 整体框架：I/O 类型泛化与投影。所谓「投影」，可以理解成「从一大块 I/O 区域里安全地切出一小块子区域」来单独操作——就像从一整张 Excel 表里框选出一个区域来处理，框选出来的部分仍然知道自己在原表的什么位置、边界在哪。这是整个系列的纲领性补丁。

📬 系列总览

② 新增动态大小的 Region 类型：以前的 I/O 区域大小往往要在编译期就定死，这个补丁引入了一个大小可以在运行时确定的 Region 类型，灵活性更高，适配更多硬件场景。

GPU/DRM 驱动：NOVA 显卡驱动的 FALCON 重构

GPU/DRM 驱动：Nova 显卡驱动的 Falcon 重构

Nova 是社区正在用 Rust 写的 NVIDIA 新一代 GPU 驱动。今天 Tim Kovalenko 提交了一个针对 Falcon 的重构补丁（第 2 版）。Falcon 是 NVIDIA 显卡里的一颗小型微控制器（可以理解成显卡内部的一个「小管家芯片」），驱动需要跟它打交道来完成复位、加载固件、启动等操作。

这次改的是什么呢？以前每次调用 Falcon 的各种操作（复位 reset、加载 load、启动 boot、邮箱 mailbox、DMA 传输，以及 GSP/FSP 相关的辅助函数），都要把「绑定的设备 dev」和「BAR0 内存映射」这两个参数一遍遍地传进去，代码里到处是重复的「管道铺设」。补丁的做法很直接：把 dev 和 BAR0 直接存进 Falcon 结构体里，以后用的时候从自己身上取就行，不用再层层传递。同时 FalconHal 改成接收一个引用。这样 API 一下子清爽了很多。

💬 配套讨论（Zulip #Nova）：往子设备里存「设备绑定引用」。Tim 在 Zulip 上说他已经根据反馈发了新版本，并表示这个合并后会继续做重构的其他部分；不过他这周末要搬家，下周中之前可能没太多时间。Alexandre Courbot 回应会尽快看。两人还聊到一个实用的小细节：用 --auto-to-cc 自动抄送维护者时，因为补丁里碰到的字段名带了「riscv」字样，结果把 RISC-V 的维护者也误抄送进来了——Alexandre 分享了他平时手动删掉这些误加维护者的习惯做法。对新手来说，这是了解「补丁该抄送给谁」这套社区礼仪的好例子。

内核模块系统：THIS_MODULE 处理与维护者归属

内核模块系统：THIS_MODULE 处理与维护者归属

这两组补丁来自 Gary Guo 和 Alvin Sun（都到了第 6 版，各 10 个补丁），都和「内核模块」这件事有关。内核模块就是那些能动态加载/卸载的功能块（比如各种驱动），系统里有个特殊的 THIS_MODULE 宏，用来指代「当前这个模块自己」。

① configfs 使用 LocalModule 来表示 THIS_MODULE：configfs 是内核里一种让用户态通过文件系统来配置内核对象的机制。这个补丁系列改进了它在 Rust 侧获取「当前模块」引用的方式，改用一个叫 LocalModule 的新抽象，让模块自引用这件事在 Rust 里表达得更干净、更安全。

📬 查看补丁

② 更新 MAINTAINERS 让它覆盖 module.rs：内核根目录有个 MAINTAINERS 文件，记录着「哪个文件归哪些人维护」。这个补丁把 module.rs 这个文件正式登记进去，明确它的维护者归属。别小看这种文件——它直接决定了你发补丁时邮件会自动抄送给谁，是社区协作的「通讯录」。

📬 查看补丁
💡 小白科普
· 内核模块（Kernel Module）：可以在系统运行时随时加载或卸载的内核代码块，大部分驱动都是模块，这样不必为了换个驱动就重启整台机器。→ 内核文档
· configfs：一种「反向」的文件系统——你在文件系统里创建目录/文件，内核就据此创建并配置内部对象，常用于运行时配置复杂内核功能。→ 内核文档

️ 虚拟化（KVM）：用 RUST 重写 EVENTFD（RFC 实验

️ 虚拟化（KVM）：用 Rust 重写 eventfd（RFC 实验提案）

这是今天最「大胆」的一个提案，由 leixiang 提交（原作者 ninol），标记为 RFC（征求意见稿，意思是「我先抛个想法，大家看看靠不靠谱」）。它要做的事是：把 KVM 虚拟化里的 virt/kvm/eventfd.c 用 Rust 重新实现一遍。

KVM 是 Linux 内核自带的虚拟机引擎。eventfd 在这里负责两个关键功能：irqfd（通过 eventfd 给虚拟机注入中断，相当于「敲门通知虚拟机有事」）和 ioeventfd（当虚拟机往某个 MMIO/PIO 地址写数据时，触发一个 eventfd 信号）。这个 Rust 版本号称做到了完整的 C ABI 兼容——也就是说它能无缝替换原来的 C 代码，外界感觉不出区别。实现上它用了 Rust 的 RAII 守卫机制来管理 SRCU、互斥锁等同步原语，靠「作用域结束自动释放」来避免忘记解锁这类经典 bug。这类把核心子系统整体 Rust 化的尝试还比较前沿，能不能被接受要看社区后续讨论。

📬 查看 RFC
💡 小白科普
· KVM：内核内置的虚拟化模块，让一台物理机能高效地跑多个虚拟机，云服务器几乎都靠它。→ 内核文档
· RAII：「资源获取即初始化」，Rust/C++ 里的一种思路——把资源（锁、内存等）绑在一个对象上，对象一离开作用域就自动释放，从根上避免「忘了释放」。→ 维基百科

构建系统与工具链

构建系统与工具链

① PowerPC 架构设定最低 rustc 版本（V16，7 补丁）：由 Miguel Ojeda 和 Mukesh Kumar Chaurasiya 推进。Rust 编译器（rustc）不同版本支持的特性不一样，不同 CPU 架构能用的最低版本也可能不同。这个系列为 PowerPC 架构明确规定了一个最低的 rustc 版本要求，是 PowerPC 上启用 Rust 支持的必经一步。已经迭代到第 16 版，说明打磨得相当细致。

📬 查看补丁

② 升级 zerocopy 库到 v0.8.52：由 Miguel Ojeda 提交。zerocopy 是内核「自带」（vendored，即把第三方库源码直接放进内核仓库一份）的一个 Rust 库，作用是安全地在「字节」和「结构体」之间转换而不用复制内存。这次连同 zerocopy-derive 一起升级。补丁说明里提到一个好消息：之前内核这边因为差异化处理而需要打补丁的大部分 SPDX 许可证标识，现在已经被上游（zerocopy 官方）按内核的请求合并进去了（而且没用内核侧暂不支持的括号写法），这样内核维护的「私货差异」就更少了，未来升级更省心。

📬 查看补丁
💡 小白科普
· rustc：Rust 的官方编译器，把 Rust 源码翻译成机器能跑的代码；内核对它有最低版本要求，因为新语法要新编译器才认。→ 官方文档
· vendoring（库内置）：把外部依赖的源码直接复制进自己仓库，好处是构建不依赖网络、版本完全可控，代价是要手动同步上游更新。→ Rust-for-Linux 说明

其他动态：设备驱动小改进

其他动态：设备驱动小改进

USB 驱动：用 pin_init::zeroed 初始化 usb_device_id，由 NVIDIA 的 Alexandre Courbot 提交。每个 USB 驱动都要声明一张「我支持哪些设备」的 ID 表（usb_device_id），系统靠它来匹配插上来的 USB 设备该用哪个驱动。这个小补丁把这张表的初始化方式改成用 pin_init::zeroed——也就是用一种更符合 Rust 风格、更安全的方式把这块结构体清零初始化，避免手写容易出错的样板代码。虽然改动不大，但属于让 Rust 驱动写起来更顺手的「日常打磨」。

📬 查看补丁
💡 小白科普
· 设备 ID 表（device_id table）：驱动用来声明「我能驱动哪些硬件」的清单，内核拿插入设备的厂商号/型号去表里对，对上了就加载这个驱动——就像给手机装驱动时系统先认一认型号。→ 内核 USB 文档

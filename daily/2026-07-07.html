Nova 增加 GETPARAM 查询 GPU 芯片型号

Nova 增加 GETPARAM 查询 GPU 芯片型号：这组补丁给 DRM ioctl 增加参数，让用户态程序能读到 GPU chipset。它影响 drm/nova，重要性在于用户态驱动、调试工具和兼容性判断首先需要知道“这到底是哪颗 GPU”。

Nova 增加可用 VRAM 大小查询

Nova 增加可用 VRAM 大小查询：同一组补丁还增加读取 usable VRAM size 的 GETPARAM 参数，帮助用户态知道实际可用显存，而不是只依赖硬件标称值。

nova-core 公共驱动 API 与 DRM 注册数据

nova-core 公共驱动 API 与 DRM 注册数据：补丁把 nova-core 向上层驱动暴露的接口和 DRM 注册信息整理出来，影响 gpu/nova-core 与 drm/nova 的连接方式。

固件 TLV 解析器 v3

固件 TLV 解析器 v3：gpu: nova-core 增加 firmware file 的 TLV parser，用于读取固件里按 Type-Length-Value 组织的数据，为后续初始化 GPU 固件打基础。

辅助总线注册讨论

辅助总线注册讨论：RFC 讨论 nova-core 是否以及如何加入 auxiliary bus registration data，参与者主要关心模块边界、设备拆分和后续驱动组合方式。

Rust 内核抽象：固件、fwctl、ID 分配与 I/O 映射

rust: firmware: request_into_buf() v3

rust: firmware: request_into_buf() v3：新增把固件请求结果放入指定缓冲区的 Rust 接口，影响 Rust 驱动加载 firmware 的方式，减少驱动自己处理底层 C API 的机会。

fwctl Rust 抽象 v6：为 firmware control 子系统引入 Rust 封装，让 Rust 驱动可以用更类型安全的方式暴露固件控制接口。

Rust 内核抽象：固件、fwctl、ID 分配与 I/O 映射

IoSysMap v6

IoSysMap v6：补齐 Rust I/O 抽象，影响设备内存映射和系统内存映射之间的表达方式。

IoCapable 安全说明补充

IoCapable 安全说明补充：把 io_read / io_write 的对齐要求写进 safety requirement，并让 Io 检查时考虑 self.addr()。这很重要，因为 MMIO 访问如果地址没对齐，轻则读错，重则触发硬件或架构异常。

小白科普：Rust-for-Linux 的核心工作之一，是把内核里的 C 接口包装成 Rust 抽象。重点不是“把 C 改写成 Rust”，而是让驱动作者在调用固件、I/O、ID 分配等内核能力时，更少踩到生命周期、对齐、空指针和错误处理的坑。

设备驱动：USB、网卡 PHY 与 CPUFREQ 的细节打磨

设备驱动：USB、网卡 PHY 与 cpufreq 的细节打磨

USB RFC：隐藏 usb::Device，用 Interface<Bound> 限制传输

USB RFC：隐藏 usb::Device，用 Interface<Bound> 限制传输：讨论重点是 Rust USB 抽象如何防止驱动在接口未绑定或状态不对时发起传输。参与者关心 API 是否能把“正确使用顺序”编码进类型系统。

qt2025 与 ax88796b PHY 改用 vertical import style

qt2025 与 ax88796b PHY 改用 vertical import style：这两组网络 PHY 补丁把 Rust use 导入改成纵向排列，影响 net/phy 下相关驱动。功能不变，但可读性更好，后续 review 和冲突处理更轻松。

rust: rcpufreq_dt import 风格调整

rust: rcpufreq_dt import 风格调整：cpufreq Rust 驱动也采用同样导入风格，保持子系统内代码样式一致。

小白科普：PHY 是网卡和物理线路之间的硬件层；cpufreq 负责 CPU 频率调节；USB interface 则是 USB 设备里的功能单元。Rust 抽象常用类型状态来表达“这个对象现在能不能用”，例如只有绑定后的接口才能发起传输。

并发 / 内存：SRCU、PG_LOCKED 与 BITMAP 连续区

并发 / 内存：SRCU、PG_locked 与 bitmap 连续区域

Rust SRCU 抽象 v10

Rust SRCU 抽象 v10：为 SRCU 增加 Rust 封装，影响内核中需要读多写少同步的 Rust 代码。SRCU 允许读侧临界区睡眠，比普通 RCU 更适合某些驱动路径。

dept 跟踪 PG_locked v19

dept 跟踪 PG_locked v19：40 个补丁让 dept 能跟踪 page lock 的等待和事件。它影响内核锁依赖分析，重要性在于能发现真实的死锁或锁顺序问题。

Rust bitmap 连续区域操作

Rust bitmap 连续区域操作：给 Rust bitmap 增加 contiguous area operations，适合资源分配器寻找一段连续 bit，例如连续页、连续队列号或连续硬件槽位。

小白科普：内核里“并发正确”很难，锁顺序错了可能死锁，读写同步错了可能 use-after-free。SRCU、dept、bitmap 这些看似底层的工具，都是驱动稳定运行的基础设施。

安全与工具链：指针打印防泄漏，CSCOPE 过滤二进制文件

安全与工具链：指针打印防泄漏，cscope 过滤二进制文件

Rust 安全指针格式化 v13

Rust 安全指针格式化 v13：修复 {:p} 的两个问题：一是宏展开时可能打印局部栈变量地址，而不是原始指针；二是直接打印原始内核地址会泄漏 KASLR 等地址布局信息。补丁影响 Rust 侧 pointer formatting，是安全性和调试正确性的双重修复。

scripts/tags.sh 避免二进制文件进入 cscope.files

scripts/tags.sh 避免二进制文件进入 cscope.files：修正 make COMPILED_SOURCE=1 cscope 时把 .rlib、.rmeta、.so 等文件加入索引的问题。影响内核开发者的代码浏览体验。

GitHub issue #355：rustc 期望功能与 bugfix 元跟踪

GitHub issue #355：rustc 期望功能与 bugfix 元跟踪：社区继续集中记录 Rust 编译器侧对内核有用的功能、缺陷修复和工具链需求。

小白科普：内核地址不能随便打印出来，因为攻击者可能利用地址信息绕过随机化防护。cscope 则是老牌代码索引工具，内核开发者常用它在巨大代码树里跳转函数和文件。

Miguel Ojeda 关注背景与复现

Tyr GPU 驱动：新增 debugfs 调试基础设施

Tyr GPU 驱动：新增 debugfs 调试基础设施

Danilo Krummrich 提交了两组共 13 个补丁，为正在开发中的 Tyr GPU 驱动搭建了 debugfs 调试接口。第一组补丁建立了 debugfs 的基础框架——你可以把 debugfs 想象成一个"调试窗口"，开发者可以通过读取特殊文件来查看驱动内部的状态。第二组补丁则具体实现了 VMs（虚拟内存空间）和 GPUVAs（GPU 虚拟地址）的 debugfs 接口，让开发者能实时查看 GPU 正在使用哪些内存区域、这些区域是怎么映射的。这对调试 GPU 内存分配错误、地址映射冲突等问题至关重要。Tyr 是一个全新的用 Rust 编写的 GPU 驱动，它的每一步进展都在验证 Rust 在复杂驱动场景中的可行性。

工作队列：为 Arc<T> 新增 cancel_work() 取消功能

工作队列：为 Arc<T> 新增 cancel_work() 取消功能

Moayad Salloum 提交了一个重要补丁，为工作队列中由 Arc<T> 持有的工作项添加了安全的 cancel_work() 函数。这解决了什么问题呢？在之前的 API 中，当你把一个 Arc<T>（一种引用计数的智能指针）提交到工作队列时，系统会调用 Arc::into_raw() 把这个指针"泄漏"给队列，只有当任务真正执行时才会通过 Arc::from_raw() 回收它。问题来了：如果驱动程序需要在任务执行前取消它（比如设备正在拔出），就没有安全的方式去做这件事，导致内存泄漏。这就像你往快递柜里放了一个包裹但收件人永远不来取——包裹就永远卡在那里了。现在 cancel_work() 提供了一个安全的方式来"取回"这个包裹。补丁经过了 kernel test robot 的自动测试和 Onur Özkan 等人的审查。

工作队列与链表：补齐 SAFETY 注释

工作队列与链表：补齐 SAFETY 注释

同样是 Moayad Salloum，他还提交了两组补丁来补充安全注释（SAFETY comments）。第一组为 Pin<KBox<T>> 的 WorkItemPointer 和 RawWorkItem 实现填写了之前标记为 SAFETY: TODO 的占位符。这些注释详细解释了为什么 unsafe 代码是安全的——比如为什么 __enqueue 使用的 work_struct 是用正确的回调函数初始化的，以及为什么类型转换是合法的。第二组补丁为链表宏 impl_has_list_links_self_ptr! 和 impl_list_item! 中的三个 SAFETY TODO 占位符做了同样的事。在 Rust-for-Linux 项目中，每一处 unsafe 代码都必须配有严格的安全论证注释，这是社区的核心质量要求。

PCI 驱动框架

PCI 驱动框架

PCI 驱动 trait 引入生命周期参数（v3，27 个补丁）

PCI 驱动 trait 引入生命周期参数（v3，27 个补丁）

这是今天最大的一组补丁！Alexandre Courbot（来自 NVIDIA）提交了第三版共 27 个补丁，为 Rust PCI 驱动的 Driver trait 添加了生命周期参数。这是什么意思呢？在 Rust 中，"生命周期"是编译器用来确保引用不会指向已经释放的内存的机制。之前的 PCI 驱动 trait 没有对设备数据的生命周期做严格约束，这意味着在某些边界情况下（比如设备热拔插时），理论上可能出现引用悬空（dangling reference）的问题。现在通过给 Driver trait 加上生命周期参数，编译器可以在编译时就保证：只要驱动在使用设备数据，这些数据就一定是有效的。打个比方，这就像给借书证加上了有效期——图书馆系统会自动确保你不会在书已经被回收后还试图去读它。Danilo Krummrich 和 Gary Guo 参与了审查。这个改动涉及面很广，需要更新所有现有的 PCI 驱动代码。

平台驱动注册：传递模块名以修复 sysfs 符号链接（v5）

平台驱动注册：传递模块名以修复 sysfs 符号链接（v5）

Shashank Balaji 提交了一组共 4 个补丁的第五版，核心改动是在驱动注册宏中传递 KBUILD_MODNAME（内核构建时的模块名）。为什么需要这个？在 Linux 的 sysfs（一个暴露设备和驱动信息的虚拟文件系统）中，每个驱动都应该有一个指向其所属模块的符号链接。但对于内建驱动（直接编译进内核而非作为模块加载的驱动），这个链接之前是缺失的，因为注册时没有传递模块名。这组补丁修复了这个问题，同时更新了 Rust 平台驱动适配器来支持新参数。Greg Kroah-Hartman（Linux 驱动子系统的维护者）参与了审查。补丁在 QEMU 虚拟机上用 x86 defconfig 配合 CONFIG_RUST=y 进行了测试。

Tegra CBB：将驱动注册从 pure_initcall 移至 core_initcall（v5）

模块参数：pr_warn 改为 pr_warn_once

模块参数：pr_warn 改为 pr_warn_once

Xiaobo Liu 提交了一个补丁，把模块参数处理中的 pr_warn（每次触发都打印警告）替换为 pr_warn_once（只打印一次）。这个看起来不起眼的改动其实很实用：想象一下，如果某个模块参数出了问题，内核日志每秒都在打印同一条警告，日志很快就会被"淹没"，你反而看不到真正重要的信息。改成 pr_warn_once 后只打印一次，既提醒了问题，又不会制造噪音。Miguel Ojeda 和 Sami Tolvanen 都参与了审查讨论，Sami 也提交了一个相关补丁专门处理空指针警告的场景。

CPU 模块：使用 unsafe_precondition_assert! 替代 debug_assert!

CPU 模块：使用 unsafe_precondition_assert! 替代 debug_assert!

Ritvik Gupta 提交了一个补丁，把 CPU 模块中 from_i32_unchecked 和 from_u32_unchecked 这两个 unsafe 函数里的 debug_assert! 替换为 unsafe_precondition_assert!。区别是什么？debug_assert! 只在调试构建中有效，而 unsafe_precondition_assert! 是 Rust-for-Linux 项目定义的宏，专门用于声明 unsafe 函数的前置条件——它更明确地表达了"调用者必须保证这个条件成立"的语义，而不仅仅是一个调试检查。Miguel Ojeda 参与了审查。这个改动也与 GitHub 上的 Issue #1232 相关联。

新增 CacheAligned 类型：便捷的缓存行对齐

新增 CacheAligned 类型：便捷的缓存行对齐

Andreas Hindborg 提交了一个补丁，新增了 CacheAligned 类型，用于轻松实现数据的缓存行对齐。在多核处理器中，如果两个不相关的变量恰好在同一条缓存行中（64 字节），当一个 CPU 核修改其中一个变量时，另一个核上包含另一个变量的缓存也会失效——这就是著名的"伪共享（false sharing）"问题，会严重拖慢性能。CacheAligned 包装器确保你的数据独占一条缓存行，避免伪共享。就像宿舍里每人一个储物柜，你整理自己的柜子不会影响室友的一样。Gary Guo 参与了审查。

📬 查看补丁
安全指针格式化支持（v12）

安全指针格式化支持（v12）

Ke Sun 提交了第 12 版补丁（共 2 个），为内核中的 Rust 代码添加安全的指针格式化（打印）支持。在内核开发中，打印指针地址是非常常见的调试手段，但直接打印原始地址可能泄露内核地址空间布局（这是一个安全隐患，攻击者可以利用它绕过 KASLR 等安全机制）。这组补丁提供了与 C 内核中 %pK/%px 类似的安全格式化方式，可以根据权限级别决定是否隐藏真实地址。已经迭代到了 v12，说明社区对 API 设计的细节非常谨慎。

️ 安全：不可信数据 API

Untrusted Data API v4（4 个补丁）

Untrusted Data API v4（4 个补丁）

Alistair 提交了第四版不可信数据（Untrusted Data）API 补丁集。这套 API 的核心思想是：从用户空间、硬件寄存器或网络收到的数据在被验证之前，都应该被标记为"不可信"。通过类型系统强制执行这一点——你拿到的不是一个普通的 u32，而是一个 Untrusted<u32>，必须经过显式的验证/转换才能变成可信的值。这就像机场安检：不管你是谁，行李必须过 X 光机才能进入候机区。这种方法可以在编译时就防止开发者不小心使用未经验证的外部数据，从根源上杜绝一大类安全漏洞（比如越界访问、注入攻击等）。v4 说明设计仍在迭代中。

Issue #2：内核依赖的 Rust unstable 特性跟踪

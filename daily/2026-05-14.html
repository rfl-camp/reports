️ GPU / DRM 驱动

Nova-core：设备卸载流程（v3，共 6 个补丁）

Nova 是社区正在用 Rust 从零编写的 NVIDIA GPU 开源驱动。今天 John Hubbard（来自 NVIDIA）提交了第三版补丁系列，共 6 个补丁，核心任务是：当驱动从设备上解绑（unbind）时，正确地执行"卸载序列"（unload sequence）。

这是什么意思呢？想象你在手机上"安全弹出" U 盘——驱动也需要类似的"优雅退场"流程：释放 GPU 固件资源、停止硬件操作、回收内存等。如果卸载流程不完整，轻则内存泄漏，重则系统崩溃。这个补丁系列已经迭代到第三版，说明社区在认真打磨这个关键流程。这是 Nova 驱动走向可用的重要一步。

Asahi GEM SHMEM 散列表问题（Zulip 热议，27 条消息）

Asahi 是为 Apple Silicon Mac 编写的 GPU 驱动，其中的 Rust DRM 绑定正在积极开发中。今天 Lyude（Red Hat）和 Daniel Almeida 在 Zulip 上进行了深入讨论，焦点是 GEM SHMEM 子系统中散列表（scatterlist）API 的严重问题。

简单来说，GPU 驱动需要管理显存，GEM（Graphics Execution Manager）是 Linux 内核中管理 GPU 内存对象的框架，SHMEM 是其中一种基于共享内存的实现方式。散列表则是描述物理内存如何分散在不同位置的数据结构——因为内存页不一定是连续的，需要一张"地图"告诉 GPU 去哪儿找数据。

Lyude 的判断是：这个 API 在内核 C 代码层面就已经存在设计缺陷，只不过 C 驱动可以用一些"非常规手段"绕过问题，但 Rust 的安全约束不允许这样做。Daniel 在尝试用 Lyude 的补丁搭建演示环境时也遇到了大量散列表相关的问题，验证了这个判断。目前的结论是：可能需要为 Rust 驱动单独设计一套更合理的抽象。

同步与并发原语

SetOnce 添加懒初始化方法

Alice Ryhl（Google，Rust-for-Linux 核心贡献者）提交了一个补丁，为 SetOnce 类型添加了懒初始化（lazy initialization）方法。

SetOnce 是一种"只能写一次"的容器——你可以在某个时刻往里面放一个值，之后这个值就"定"了，不能再改。这在内核中很常见，比如设备驱动初始化时设置某个全局配置：第一次设好之后就不该再变。

新增的"懒初始化"方法允许你说"如果还没初始化过，就用这个函数来初始化"。这避免了重复检查和竞态条件，让代码更简洁、更安全。这个补丁已经收到了 Andreas Hindborg 的审查。

SetOnce 支持 pin_init 讨论

Lyude（Red Hat）在邮件列表上参与了关于让 SetOnce 支持 pin_init 的讨论。pin_init 是 Rust-for-Linux 中一套特殊的初始化机制——在内核中，有些数据结构一旦创建就不能被移动到其他内存位置（因为有指针指向它们），这种情况叫"pinned"（钉住）。pin_init 让你可以安全地"就地初始化"这些不可移动的对象。让 SetOnce 支持 pin_init 意味着你可以在钉住的内存位置上安全地使用"只写一次"的语义，这对 DRM 驱动等场景非常有用。

工作队列：添加 cancel_sync 支持

同样来自 Alice Ryhl 的补丁，为 Rust 的工作队列（workqueue）抽象添加了 cancel_sync（同步取消）支持。

工作队列是内核中"延后执行任务"的机制——好比你点了外卖，系统把你的"取餐"任务放进队列里，等骑手到了再执行。但有时候你想取消这个任务（比如你改主意了），而且你需要确保取消完成后任务确实停了、不会再执行。cancel_sync 就做这件事：同步地取消一个已排队的工作项，并等它真正结束。这对于驱动卸载时清理未完成的异步操作至关重要——你不能让驱动都卸载了，结果还有个幽灵任务在后台跑。

️ 安全抽象与子系统 API

️ 安全抽象与子系统 API

Rust 封装：capable() 和 ns_capable() 权限检查

这个补丁为内核的权限检查机制提供了 Rust 安全封装。Linux 内核中，capable() 用来检查当前进程是否拥有某种特权能力（比如 CAP_SYS_ADMIN 是"系统管理员能力"，CAP_NET_RAW 是"原始网络操作能力"）。ns_capable() 则是在特定命名空间（namespace）下做同样的检查。

这些函数在内核中无处不在——几乎所有涉及安全的操作都要先检查"你有没有权限干这事"。有了 Rust 封装后，Rust 驱动就不需要写 unsafe 代码来调用这些 C 函数了，减少了出错的可能性。kernel test robot 也参与了自动化测试验证。

configfs：从 C 侧添加默认组的 Rust API

Andreas Hindborg 提交的补丁，为 configfs 子系统添加了 Rust API。configfs 是一种基于文件系统的配置接口——用户可以通过创建/删除目录和文件来配置内核子系统，就像你在"设置"应用里调参数一样，只不过这里的"设置界面"是文件系统。

这个补丁具体是让 Rust 代码可以从 C 侧添加"默认组"（default groups）。所谓默认组就是 configfs 目录树中自动创建的子目录，用于预置一些配置项。这对于需要和现有 C 代码互操作的 Rust 驱动来说是关键能力。

📬 查看补丁
fault-inject：故障注入的 Rust API

同样来自 Andreas Hindborg 的补丁，为内核的故障注入框架（fault-inject）提供了 Rust 接口。故障注入是一种测试技术——你故意让某些操作失败（比如让内存分配随机失败），来测试你的代码是否能正确处理错误情况。

这就像消防演习：你明知道不是真的着火，但通过模拟火灾来检验逃生流程是否通畅。在内核开发中，故障注入是确保驱动鲁棒性的重要手段。有了 Rust API，Rust 驱动就可以方便地利用这个框架进行可靠性测试了。

⚡ 抢占与中断管理

⚡ 抢占与中断管理

用独立计数器跟踪 NMI 嵌套（11 个补丁）

Joel Fernandes（NVIDIA）提交了一个大型补丁系列（11 个补丁），目标是将 NMI（Non-Maskable Interrupt，不可屏蔽中断）的嵌套跟踪从现有的抢占计数器中分离出来，使用独立的 per-CPU 计数器。

这需要一点背景知识：CPU 在执行代码时可能被中断打断。普通中断可以被暂时屏蔽（"别打扰我"），但 NMI 是"不可屏蔽"的——它就像 VIP 电话，无论你在忙什么都必须接。NMI 甚至可能嵌套发生（正在处理一个 NMI 时又来一个）。

以前内核用"抢占计数器"（一个多用途的数值）来跟踪 NMI 嵌套层数，但这让计数器变得很拥挤、逻辑复杂。这个补丁系列把 NMI 计数单独拿出来放到 per-CPU 变量里（每个 CPU 核心有自己的计数器），让代码更清晰、性能更好。这个改动对 Rust-for-Linux 也有影响，因为 Rust 代码中与抢占相关的抽象也需要相应调整。

代码风格与文档

rust-analyzer 文档更新

Onur Özkan 提交了一个文档补丁，收到了 Miguel Ojeda 和 Gary Guo 等 4 位审查者的反馈。问题是：当你在一个全新的内核源码目录中按照文档设置 rust-analyzer（Rust 的 IDE 智能补全工具）时，仅仅生成 rust-project.json 文件是不够的。

如果你只做了这一步，一开始似乎一切正常，但过一会儿 LSP（语言服务器协议）就会在处理过程宏（proc macro）或绑定类型时报错。原因是还需要先运行 make prepare 来生成一些编译时依赖的文件。这个补丁更新了文档，建议在运行 rust-analyzer 目标之前先执行 prepare，这样就不会踩坑了。虽然是个小改动，但对新手体验影响很大——毕竟设置开发环境是上手的第一步。

📬 查看补丁
alloc 模块导入语句风格统一（v2，共 2 个补丁）

Danilo Krummrich 提交了两个补丁，将 rust/kernel/alloc 模块中所有的 use 导入语句改成了"内核垂直风格"（kernel vertical style）。什么意思呢？

在普通 Rust 代码中，你可能会写 use alloc::vec::Vec; 这样的单行导入。但内核的 Rust 代码约定了一种特别的风格：每个导入项都单独占一行，纵向排列，便于在 diff 中清晰看到变更。这两个补丁分别处理了代码本体和文档测试（doctest）中的导入语句，同时顺手删除了一些被 prelude::*（预导入集）已经覆盖的冗余导入。

这类"代码清洁"工作看似琐碎，但对于一个有上百名贡献者的项目来说，统一的代码风格能大幅降低代码审查和维护的成本。

构建系统与工具

kconfirm：新的内核配置确认工具（RFC v2）

Julian Braha 提交了 kconfirm 工具的第二版 RFC（Request for Comments，征求意见稿），引发了 Miguel Ojeda 和 Nicolas Schier 等 5 位维护者的讨论。

kconfirm 想要解决的问题是：Linux 内核的编译配置选项非常多（几千个！），有时候你修改了一个配置选项，不确定它到底有没有生效，或者不确定它和其他选项之间有没有冲突。kconfirm 就是一个帮你确认和验证内核配置的工具。

这是第二版 RFC，说明作者根据社区第一轮反馈做了修改。具体的讨论细节涉及工具的适用范围、与现有 Kconfig 工具链的关系，以及是否应该作为内核源码树的一部分被维护。目前还在讨论阶段，尚未达成最终共识。

为 Delta 时间类型实现 Display trait

这个小补丁为 Rust 内核代码中的 Delta 类型实现了 Display trait。Delta 表示两个时间点之间的差值（时间间隔），实现 Display 意味着你现在可以直接用 println!("{}", delta) 来打印一个时间间隔的可读表示，而不是看到一堆原始数字。

这虽然是个小改进，但对于调试和日志记录来说非常实用——当你在排查驱动中的延时问题时，能直接看到"这个操作花了多少微秒"比看一个裸数字方便得多。Miguel Ojeda 参与了代码审查。

️ GPU / DRM 驱动

修复 DRM 设备不安全初始化问题

Alice Ryhl 发现并修复了 drm::Device::new 中一个内存安全问题。简单来说，之前的代码在创建 DRM 设备对象时，初始化的顺序和方式不正确，可能导致"未定义行为"——这在 Rust 里是非常严重的事情，因为 Rust 的核心卖点之一就是保证内存安全。这个补丁修正了初始化流程，确保设备对象在完全准备好之前不会被外部代码访问到。Gary Guo 参与了代码审查。

修复 Device 文档注释中的错误类型名

Hsiu Che Yu 提交了一个文档修复补丁：在 DRM Device 的文档注释中，不变量（invariant）部分错误地引用了 struct device，但实际应该是 struct drm_device。虽然这只是文档问题不影响运行，但准确的文档对于理解代码至关重要——尤其是安全相关的不变量描述，写错了会误导后续的开发者。Alice Ryhl 审查了这个补丁。

GEM 共享内存：新增 DmaResvGuard 辅助工具 (v13)

Alexandre Courbot 提交了一组 5 个补丁，为 DRM 的 GEM 共享内存（shmem）子系统添加了 DmaResvGuard 辅助类型。在 GPU 驱动中，多个组件（CPU、GPU、甚至多个 GPU）可能同时访问同一块内存，因此需要一个"预留锁"（DMA reservation）来协调访问。这个 Guard 类型就像一个"通行证"，确保你在持有它的时候，别人不会同时修改这块内存。已经迭代到第 13 版了，说明社区对 API 设计非常审慎。Alice Ryhl 参与了审查。

GEM 共享内存：引入 shmem::SGTable (v13)

同一系列的另一组补丁，由 Deborah Brouwer 提交，引入了 shmem::SGTable 抽象。SGTable（Scatter-Gather Table，散集表）是 GPU 驱动中一个核心数据结构——它描述了一块物理上分散的内存页在虚拟空间中如何组合成一块连续的缓冲区。你可以把它想象成一个"拼图地图"，告诉 GPU 去哪些零散的内存位置拼出它需要的完整图像数据。Alice Ryhl 审查了这些补丁。

DmaFence 讨论进展

在 Zulip 的 DRM 频道中，Philipp Stanner 更新了关于 DmaFence（DMA 围栏）的讨论合并请求。DmaFence 是 GPU 驱动中用于同步操作的关键机制——当 GPU 还在处理一帧画面时，CPU 不应该去修改这帧数据，DmaFence 就是这个"等一等"的信号。这次更新的重点包括：允许预分配围栏回调（减少运行时内存分配压力）和预分配围栏本身（这个想法来自 Daniel Almeida）。Philipp 正在征求 Daniel Almeida 和 Boris Brezillon 的反馈。

Nova 核心（NVIDIA 开源 GPU 驱动）

修复 VBIOS 读取越界问题 (v3)

Alexandre Courbot 提交了一组 11 个补丁，修复了 Nova 核心在解析 VBIOS（显卡 BIOS）时多处读取超过 BIOS_MAX_SCAN_LEN 上限的问题。VBIOS 就像显卡的"出厂设置说明书"，记录了显卡的硬件参数和初始化配置。如果驱动在读取这些数据时越界，轻则读到垃圾数据导致驱动行为异常，重则可能引发安全问题。这组补丁对各种可能越界的场景进行了逐一排查和修复。Joel Fernandes 参与了审查。

📬 查看补丁
VBIOS：优先使用第一个 PCI-AT 和 FWSEC 镜像 (v3)

同样是 VBIOS 相关的改进，Alexandre Courbot 的另一组补丁修改了 Nova 核心选择 VBIOS 镜像的策略。一块显卡的 VBIOS 中可能包含多个镜像（比如不同格式、不同用途的），之前的代码在选择时没有优先使用第一个匹配的 PCI-AT 格式和 FWSEC（固件安全）镜像。这个补丁让驱动更明确地选择正确的镜像，避免加载了错误的固件数据。Gary Guo 审查了代码。

📬 查看补丁
新增 GA100 芯片支持 (v5)

Alexandre Courbot 提交了 6 个补丁，为 Nova 核心驱动添加了 GA100 芯片的支持。GA100 是 NVIDIA Ampere 架构的一款数据中心级 GPU（你可能听说过 A100，GA100 就是它的核心芯片代号）。这意味着 Nova 这个用 Rust 编写的 NVIDIA 开源驱动正在逐步扩大硬件覆盖范围，从最初的概念验证走向实际可用。这组补丁已经迭代到第 5 版，可见社区对代码质量要求很高。

📬 查看补丁
设备地址类型包装器任务 (v6)

Danilo Krummrich 提交了 2 个补丁，为 Nova 核心添加了设备地址类型的包装器。在 GPU 驱动中，需要区分不同类型的地址（比如 CPU 看到的物理地址、GPU 看到的虚拟地址、PCIe BAR 地址等），如果搞混了就会写到错误的内存位置。Rust 的类型系统非常适合解决这类问题——通过定义不同的类型，编译器就能在编译时帮你发现地址类型混用的错误，而不用等到运行时才崩溃。

简化 program_brom：移除不必要的错误处理

Alexandre Courbot 发现 Nova 核心中的 program_brom 函数实际上不可能失败，但之前的代码却返回了 Result 类型，迫使所有调用方都要处理一个永远不会发生的错误。这个补丁把返回类型改为直接返回值，去掉了多余的错误处理逻辑。这是一个典型的 Rust 代码风格改进——让类型签名准确反映函数的实际行为，减少不必要的复杂度。

⚡ PowerPC 架构 Rust 支持

为 ppc64le 启用 Rust 支持 (V15)

Mukesh Kumar Chaurasiya 提交了一组 7 个补丁，目标是在 PowerPC 64 位小端（ppc64le）架构上启用 Rust。目前 Linux 内核中的 Rust 支持主要针对 x86_64 和 ARM64 架构，PowerPC 是另一个重要的服务器架构（IBM 的 POWER 系列处理器就用它）。这组补丁修改了内核的构建系统配置，使得在 PowerPC 平台上可以编译和链接 Rust 代码。已经迭代到第 15 版了！Miguel Ojeda 也参与了这项工作。

添加 PowerPC Rust 底层支持 (V15)

设备驱动框架

设备驱动框架

串口设备总线（serdev）Rust 抽象 (v7)

Markus Probst 提交了一组 4 个补丁，为内核中的 serdev（串口设备总线） 添加了 Rust 语言的抽象层。串口设备总线是 Linux 内核中管理通过串口（UART）连接的设备的框架——想象一下，你的主板上通过一根串口线连着一个微控制器（MCU），serdev 就是管理这种连接的"翻译官"。这个抽象层的第一个实际用户将是 Synology NAS 设备中的 MCU 驱动。另外，Kari Argillander 也表示计划用它来编写一个看门狗驱动（watchdog driver，用于在系统卡死时自动重启）。已经迭代到第 7 版了，API 设计逐渐成熟。

辅助设备总线：添加注册数据

Danilo Krummrich 提交了 2 个补丁，增强了 Rust 中辅助设备总线（auxiliary bus）的抽象。辅助设备总线是 Linux 内核中一种较新的设备模型——当一个物理设备需要暴露多个逻辑子设备时（比如一块网卡同时支持网络功能和 RDMA 功能），就可以通过辅助设备总线来组织。这次的补丁添加了在注册辅助设备时携带额外数据的能力，让驱动可以在设备注册阶段就传递必要的配置信息。Alexandre Courbot 参与了审查。

修复 block 子系统注释错误

Hsiu Che Yu 提交了一个补丁，修复了 Rust 块设备（block）子系统中注释的标签引用错误——代码中状态标签的名称和注释中提到的不一致。Andreas Hindborg 审查并确认了这个修复。虽然只是注释问题，但块设备是 Linux 存储栈的核心（硬盘、SSD 都是块设备），注释准确性对于维护者理解状态机逻辑非常重要。

️ 内核基础设施与工具

指针工具：新增 panic 版本的索引投射 (5 patches)

Alexandre Courbot 提交了一组 5 个补丁，为 Rust 内核代码中的指针操作模块（rust/kernel/ptr）添加了一个新功能：带 panic 的索引投射（panicking index projection）。在内核中操作数组或切片时，如果索引越界，有两种策略：一种是返回错误让调用方处理，另一种是直接 panic（内核崩溃）。这个新变体适用于那些"如果索引越界就说明代码有 bug，应该立即崩溃"的场景——类似于 Rust 标准库中 [] 操作符的行为。Gary Guo 参与了审查。

Jesung Yang 提交了 2 个补丁，为 scripts/generate_rust_analyzer.py 脚本添加了版本管理功能。这个脚本的作用是生成 rust-analyzer（Rust 的 IDE 智能提示工具）所需的配置文件，让开发者在 VS Code 等编辑器中编辑内核 Rust 代码时能获得代码补全、跳转定义等功能。添加版本管理后，当配置格式发生变化时，工具可以自动检测并提示开发者更新，避免因为格式不兼容导致 IDE 功能失灵。Tamir Duberstein 参与了审查。

设备树绑定：AS5600 磁性位置传感器

Muchamad Coirul Anwar 提交了一个 RFC（征求意见稿）补丁，为 AMS AS5600 磁性旋转位置传感器添加设备树绑定。设备树（Device Tree）是嵌入式 Linux 中描述硬件配置的数据结构——告诉内核"这个传感器连在 I2C 总线的哪个地址上"之类的信息。AS5600 是一个常见的磁编码器，可以精确测量旋转角度，常用于电机控制和机器人。Krzysztof Kozlowski 对设备树绑定的格式提出了审查意见。虽然这个传感器驱动本身可能用 C 写，但它出现在 Rust-for-Linux 的讨论中，可能预示着未来会有 Rust 版本的 IIO（工业 I/O）驱动。

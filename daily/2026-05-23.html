️ 设备驱动生命周期大重构（27 补丁系列）

️ 设备驱动生命周期大重构（27 补丁系列）

这件事为什么重要？

这是今天最重量级的更新。Danilo Krummrich 提交了第 4 版（v4）的「Higher-Ranked Lifetime Types for device drivers」系列补丁，一共 27 个补丁，几乎改写了 Rust 设备驱动框架的核心架构。这个系列由 Greg KH（Linux 设备驱动子系统维护者）参与审查。

这件事为什么重要？简单来说，以前用 Rust 写内核驱动时，如果你要访问硬件资源（比如 PCI 设备的内存映射区域），需要用一个叫 Devres<T> 的包装器。这就像你每次想用家里的钥匙开门，都要先去物业登记一样——虽然安全，但很麻烦。重构之后，驱动可以直接持有设备资源的引用，编译器会自动保证这些引用不会在设备解绑之后还被使用。这既更高效，也更符合 Rust 的设计哲学。

以下是各个补丁的详细内容：

① 移除 ForeignOwnable 的 'static 约束（作者：Gary Guo）
之前 ForeignOwnable trait 要求数据必须是 'static（永久存活的），这限制太严格了。这个补丁通过在 GAT（泛型关联类型）上添加 Self: 'a 约束，放宽了这个限制。打个比方：以前要求你寄存的东西必须是永久保存的，现在只要在寄存期间有效就行。

📬 查看补丁
② 将 'static 约束移至构造函数

② 将 'static 约束移至构造函数（作者：Gary Guo）
配合上一个补丁，把 'static 约束从驱动数据方法和总线适配器实现中移除，改为只在 Registration（驱动注册）构造时检查。这让驱动内部代码更灵活，只在"注册驱动"这个入口处做一次严格检查。

📬 查看补丁
③ 解耦驱动私有数据与驱动类型

③ 解耦驱动私有数据与驱动类型
新增了一个 Data<'bound> 关联类型，让驱动的「私有数据」不再绑定在驱动结构体本身上。这就像把"行李"从"旅客"身上分离出来——行李有自己的生命周期标签，不再非要跟旅客绑在一起。这样做的好处是避免了在驱动 trait 上引入一个全局生命周期参数，让代码更干净。

📬 查看补丁
④ 在 devres 释放前先丢弃驱动数据

④ 在 devres 释放前先丢弃驱动数据
修改了设备解绑的清理顺序：先执行 post_unbind_rust 回调（丢弃驱动数据），再释放 devres 资源。这个顺序很关键——就像你退房时应该先收拾好自己的东西（驱动数据），再让酒店打扫房间（释放系统资源）。顺序搞反了可能导致驱动数据引用已释放的资源，产生悬垂指针。

📬 查看补丁
⑤ 为多种总线设备实现 Sync

⑤ 为多种总线设备实现 Sync
分别为 PCI、Platform、Auxiliary、USB 和通用 Device 的 Device<Bound> 类型实现了 Sync trait。Bound 只是一个零大小的标记类型，不影响底层数据结构的线程安全性。实现 Sync 之后，驱动就可以把 &'bound Device<Bound> 引用存储在自己的私有数据中，并安全地在多个线程间共享。这是整个生命周期重构的前提条件之一。

⑥ 让 Core/CoreInternal 带生命周期参数

⑥ 让 Core/CoreInternal 带生命周期参数
Device<Core> 的引用只在 probe 回调期间有效，不是整个绑定周期。这个补丁给 Core 和 CoreInternal 加上了生命周期参数，让类型系统能精确表达"这个引用只在 probe 期间有效"这件事。这避免了驱动不小心把 probe 阶段的临时引用存到长期数据结构中。

📬 查看补丁
⑦ 让各总线的 Driver trait 带生命周期参数

⑦ 让各总线的 Driver trait 带生命周期参数
分别修改了 PCI、Platform、Auxiliary、USB、I2C 总线的 Driver trait，给关联类型 Data 加上 'bound 生命周期。修改后，probe() 和 unbind() 回调会自动获得正确的生命周期标注。这意味着驱动的私有数据可以直接通过引用持有设备资源，编译器会在编译期保证引用的有效性——不再需要运行时检查。

⑧ PCI Bar 生命周期参数化 + 文档更新
Bar（PCI 基址寄存器映射）也被加上了生命周期参数，使其能直接绑定到设备的绑定周期。同时更新了驱动模块文档，反映基于 GAT 的 Data 类型的新用法。

生命周期（Lifetime）：Rust 用来追踪引用有效期的机制。编译器通过生命周期标注确保你不会使用已经被释放的数据，从根源上杜绝"悬垂指针"问题。📖 学习 Rust 生命周期
GAT（泛型关联类型）：Rust 的高级类型特性，允许 trait 的关联类型带有自己的泛型参数（包括生命周期）。这让抽象接口能更精确地描述数据的所有权和借用关系。📖 了解关联类型
Devres：内核的"设备资源管理"机制（Device Resource Management），在设备解绑时自动清理资源，防止资源泄漏。📖 内核 devres 文档

内核同步原语的 RUST 封装

内核同步原语的 Rust 封装

SRCU 抽象 v3（Onur Özkan）

SRCU 抽象 v3（Onur Özkan）
这是一个为"可睡眠 RCU"（Sleepable RCU）提供 Rust 安全封装的补丁系列，共 3 个补丁，目前已迭代到第 3 版。RCU 是 Linux 内核中一种高性能的并发读取机制——想象一个图书馆，读者可以随时进来看书，不需要排队等待；而管理员要替换一本书时，会等所有正在看旧书的读者离开后才回收旧书。SRCU 是 RCU 的增强版，允许读者在"阅读期间"做一些可能需要等待的操作（比如访问磁盘），而普通 RCU 不允许这么做。

这个补丁提供了 FFI 辅助函数和一个基于 guard（守卫）模式的安全 API。读者获取一个 guard 对象进入临界区，guard 被丢弃时自动退出。清理工作通过 PinnedDrop 实现，确保所有待处理的宽限期和回调都被正确排空。

📬 查看补丁
工作队列 cancel_sync 支持（Onur Özkan）

工作队列 cancel_sync 支持（Onur Özkan）
这个补丁为 Rust 的工作队列（workqueue）抽象添加了 cancel_sync 支持。工作队列是内核中"排队执行任务"的机制——你把一件事扔进队列，内核会找个合适的时机帮你执行。cancel_sync 的作用是"同步取消"一个还在排队的任务：不仅取消它，还要等它真正停下来再返回。Danilo Krummrich 参与了代码审查，目前已有 2 位审查者。

自旋锁与中断处理讨论（Zulip）

自旋锁与中断处理讨论（Zulip）
Manos Pitsidianakis 在 Zulip 上提出了关于"带中断禁用的自旋锁"（Spinlocks with IRQs）的话题。他指出相关的讨论帖非常长，询问当前工作的进展状态，并建议更新 GitHub issue #1115 来反映最新进展。自旋锁在中断上下文中使用时需要特别小心——如果一个线程持有自旋锁时被中断打断，而中断处理程序又试图获取同一个锁，就会死锁。因此需要在获取锁的同时禁用中断。这个 Rust 封装需要在类型系统中正确表达这些约束。

️ VIRTIO 虚拟化驱动

️ VirtIO 虚拟化驱动

VirtIO RFC 系列拆分策略讨论（Zulip）

VirtIO RFC 系列拆分策略讨论（Zulip）
Andreas Hindborg 在 Zulip 上转述了 Manos Pitsidianakis 的一个问题：由于 VirtIO 驱动的工作涉及多个子系统（virtio 核心和 hw_random 硬件随机数生成器），应该把补丁系列拆成按子系统分开的小系列，还是合并成一个大系列提交？

Onur Özkan 也参与了讨论，涉及了另一个重要原则：能不能提交当前没有驱动使用的抽象代码？答案是否定的——Rust-for-Linux 社区遵循"不添加没有用户的代码"的原则。这意味着每个抽象层都必须有真正使用它的驱动代码一起提交，避免出现"写了封装但没人用"的情况。

此外，Onur 提到他已经按照 Rust-for-Linux 文档的建议，向 hw_random 子系统的维护者发送了邮件知会，但暂时未收到回复。他打算如果继续没有回复，就直接在 LKML（Linux 内核邮件列表）上发布补丁。社区成员建议这是合理的做法。

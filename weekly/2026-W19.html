类型安全与错误处理

类型安全与错误处理

PhysAddr 升级为 newtype——让编译器帮你抓 Bug

由 Favilances Noir 提交的这个补丁，将内核中的 PhysAddr（物理地址类型）从一个简单的类型别名（type PhysAddr = phys_addr_t）改为一个真正的独立类型（newtype 模式）。此前，PhysAddr 本质上就是一个普通整数，意味着你可以把一个毫不相关的数字当做物理地址来用，编译器完全不会报错——这就好像你的门牌号和电话号码都是纯数字，如果没有标签区分，很容易把电话号码当成地址去寄快递。改为 newtype 后，Rust 的类型系统会在编译时阻止这种混用，从源头杜绝一类潜在的内存安全问题。该补丁收到了 Danilo Krummrich 和 Onur Özkan 等 4 位审阅者的反馈，讨论较为活跃。

Error 类型实现 Display trait——错误信息更友好

Arnav Sharma 为内核的 Error 类型实现了 fmt::Display trait。此前只有 Debug 实现，输出的格式类似 EPERM()，带有括号和调试信息，适合开发者在日志里排查问题，但对用户不够友好。新增的 Display 实现会输出更干净的 EPERM 格式，这是 Rust 社区的惯用做法——Debug 给开发者看，Display 给用户看。这个改动看似简单，但它让内核 Rust 代码更加符合 Rust 生态的惯例（idiomatic），也为将来更复杂的错误处理链打下基础。Onur Özkan 参与了审阅。

同步原语：SRCU 抽象进入 V2

同步原语：SRCU 抽象进入 v2

为内核 Rust 代码带来 SRCU 支持

Onur Özkan 提交的 SRCU（Sleepable Read-Copy-Update）Rust 抽象已经迭代到 v2 版本，包含 3 个子补丁。SRCU 是 Linux 内核中一种重要的同步机制，它是 RCU 的变体，允许读取端在持有锁的情况下睡眠——这在原始 RCU 中是不允许的。想象一下：RCU 就像一个"免打扰"的阅览室规则，你可以自由进出阅读，但不能在里面睡觉；SRCU 则放宽了这个限制，允许你在阅读时打个盹。这对于需要在读取路径中执行可能阻塞的操作（比如访问慢速设备）的场景非常有用。Gary Guo 参与了代码审阅，社区正在完善这个抽象的 API 设计。

️ GPU/DRM 驱动

️ GPU/DRM 驱动

修复 drm::Device::new 中的 unsound 初始化问题

Gary Guo 发现并修复了 DRM（Direct Rendering Manager，图形渲染管理器）子系统中 drm::Device::new 函数的一处 unsound 问题，补丁已进入 v2。所谓 "unsound"，在 Rust 术语中是一个非常严重的词——它意味着 safe Rust 代码可能触发未定义行为（Undefined Behavior），相当于安全承诺被打破了。具体来说，这个问题出在设备初始化的过程中，某些安全不变量（safety invariant）没有被正确维护。Danilo Krummrich（DRM Rust 绑定的主要维护者）参与了审阅。这类修复虽然对终端用户不可见，但对整个 Rust-for-Linux 项目的可靠性至关重要——如果基础抽象不健全（unsound），建立在其上的所有驱动代码都可能受影响。

📬 查看补丁
Nova 驱动讨论：寄存器定义的代码组织

在 Zulip 的 Nova 频道中，Alexandre Courbot 发起了一个 RFC（征求意见）讨论：是否应该把 GPU 的寄存器定义移到实际使用它们的模块中，而不是集中放在一个大文件里。这是一个代码组织层面的设计问题。Nova 是正在开发中的开源 NVIDIA GPU 驱动（用 Rust 编写），寄存器定义是驱动与硬件交互的基础——每个寄存器就像硬件上的一个"按钮"或"旋钮"，驱动通过读写寄存器来控制 GPU。把定义放在使用处可以提高代码的局部性和可维护性，但也可能导致定义分散。讨论刚刚开始，Alexandre 鼓励大家积极提问。

驱动清理：告别 SYNCLINK_GT

驱动清理：告别 synclink_gt

移除已损坏的 synclink_gt 串口驱动

Ethan Nelson-Moore 提交了移除 synclink_gt 驱动的 v2 补丁。这个串口（TTY）驱动早在 2023 年 7 月就被标记为 BROKEN（已损坏），原因是它存在严重的结构性问题，而且自 2016 年以来就没有用户使用的证据。将近 3 年过去了，依然没有人站出来修复它或表示还在使用，因此社区决定将其彻底移除。这个补丁收到了 Andrew Lunn 和 Greg Kroah-Hartman（Linux 稳定版维护者、TTY 子系统维护者）等 5 位审阅者的反馈，讨论较为充分。虽然这不是一个 Rust 相关的补丁，但它被发送到了 rust-for-linux 邮件列表，可能与未来用 Rust 重写某些驱动的规划有关。移除过时代码是内核维护的重要工作——减少维护负担，降低安全风险。

构建工具与开发体验

rust-analyzer 配置生成脚本新增版本管理

Tamir Duberstein 持续改进 generate_rust_analyzer.py 脚本，这次提交的是 v5 版本（包含 2 个子补丁），为脚本引入了版本管理基础设施。rust-analyzer 是 Rust 开发者最常用的 IDE 插件，提供代码补全、跳转定义、类型提示等功能。但内核的构建系统比较特殊（使用 Kbuild 而非 Cargo），因此需要一个专门的脚本来生成 rust-analyzer 所需的配置文件。加入版本管理意味着当脚本输出格式发生变化时，可以更好地处理兼容性问题，避免开发者升级后 IDE 突然不工作。这个补丁已经经过多轮迭代（v1 到 v5），说明社区对开发体验的细节非常重视。
